Joyfill npm Beta Packages Carried Import-Time RAT Loader

Two prerelease packages in the @joyfill npm scope included bundled JavaScript that could execute when imported and retrieve follow-on malware using blockchain-hosted instructions.

Socket

What happened

Socket reports that two Joyfill beta releases on npm were compromised: @joyfill/layouts@0.1.2-2773.beta.0 and @joyfill/components@4.0.0-rc24-2773-beta.4. The malicious code was appended into built package artifacts and, at least in the layouts package, ran when the CommonJS entrypoint was loaded rather than during npm install. The implant used transactions on Tron, Aptos, and BNB Smart Chain as part of its payload resolution flow and could reach a Node.js remote-access trojan associated by code overlap with DEV#POPPER. A second branch attempted to fetch and decrypt a boot payload from 23[.]27[.]13[.]43/$/boot using a marker header. The source does not establish how the compromise occurred, whether through a developer machine, repository, CI system, or npm publishing credential.

Key findings

  • Affected npm versions: @joyfill/layouts@0.1.2-2773.beta.0 and @joyfill/components@4.0.0-rc24-2773-beta.4.
  • The malicious code was present at bundle time according to source map evidence, not merely injected into a final tarball after build.
  • @joyfill/layouts is the higher-risk artifact because the implant executes when the module is imported; npm install --ignore-scripts would not prevent execution after import.
  • @joyfill/components contained the same injected code in multiple dist files, but Socket observed that the bundled require behavior likely prevented normal execution in that artifact. It should still be treated as compromised.
  • Previously reviewed versions @joyfill/layouts@0.1.1 and @joyfill/components@4.0.0-rc24 reportedly did not contain the implant.
  • The final payload was assessed as capable of host reconnaissance, remote command or JavaScript execution, file upload, clipboard access, and modification of developer-tool files.

Affected ecosystems

npm, JavaScript/Node.js applications, React applications using Joyfill components, CI/build systems, developer workstations, test runners, and server-side rendering environments that imported the affected packages

Security analysis

This incident is a useful reminder that prerelease packages can carry production-grade supply-chain risk even when overall package download numbers are modest or ambiguous. The affected Joyfill versions were beta/RC builds, so the public weekly download count for the packages does not indicate how many users actually installed the compromised releases. The most important exposure question is not whether install scripts ran, but whether the package was imported by Node.js in a developer, CI, test, SSR, or build context. The reported blockchain transaction lookup pattern also complicates simple domain-based detection, because the loader can use public chains as an indirection layer for retrieving encrypted instructions. The available reporting does not prove the attacker’s initial access path, so organizations should avoid assuming this was only an npm-token issue; repository, build, and workstation compromise remain possible based on the evidence provided.

Defender actions

  • Search package-lock.json, yarn.lock, pnpm-lock.yaml, npm logs, artifact manifests, and SBOMs for @joyfill/layouts@0.1.2-2773.beta.0 and @joyfill/components@4.0.0-rc24-2773-beta.4.
  • Treat any system that imported @joyfill/layouts@0.1.2-2773.beta.0 as potentially compromised, including CI runners and developer machines; prioritize credential review for npm tokens, source-control tokens, cloud credentials, and secrets available to build jobs.
  • Downgrade or pin to known-unaffected versions and block the affected prerelease versions in dependency policy tooling.
  • Look for outbound connections or attempted connections to 23[.]27[.]13[.]43, especially requests to /$/boot with unusual Sec-V-style headers, while recognizing that blockchain-based retrieval may reduce reliance on a single command-and-control endpoint.
  • Review build artifacts for unexpected appended or obfuscated JavaScript in Joyfill bundles, particularly around dist/index.js, dist/index.esm.js, dist/joyfill.min.js, and source-map references to src/utils/reactGridLayoutUtils.js.
  • If exposure is confirmed, rotate credentials from affected environments and rebuild from clean runners or workstations before republishing internal artifacts.

Source notes

  • Primary source: Socket Research Team report published July 28/30, 2026, describing two compromised Joyfill npm beta releases.
  • Attribution to DEV#POPPER/PolinRider is based on reported code and indicator overlap, not a definitive attribution of the Joyfill compromise to a specific threat actor.
  • The source states that other checked public @joyfill packages did not contain the same signature, but defenders should still validate their own dependency trees and cached artifacts.
