Malicious NuGet .NET tools posed as game cheats and installed Windows surveillance payloads

A campaign of 11 NuGet DotnetTool packages used game-utility themes to deliver a second-stage Windows executable, with telemetry and control tied to Google Sheets and other hosted infrastructure.

Socket

What happened

Socket reported 11 malicious NuGet packages published as .NET command-line tools that impersonated game cheats, bots, calculators, and control panels. The packages acted as first-stage downloaders: after installation and execution through the .NET tool mechanism, they retrieved a Windows payload named pepesoft.exe from GitHub Releases and Hugging Face locations associated with the username pepegit666. The recovered payloads were PyInstaller-packed Python applications with licensing, telemetry, hardware-binding, and remote ban-list behavior; some builds also exposed Telegram-based screenshot control. The source does not provide the full package list in the supplied snippet, so defenders should consult the original IOC list before scoping by package name alone.

Key findings

  • The affected ecosystem is NuGet, specifically packages using the DotnetTool package type and installed via dotnet tool install.
  • The packages masqueraded as utilities for games including Albion Online, GTA5RP, GrandRP, Majestic RP, RMRP, Amazing RP, Lineage 2, Throne and Liberty, and Russian Fishing 4, plus generic trigger-bot or calculator-themed tools.
  • Each package bundled a .NET downloader under tools/net8.0/any/ and shared supporting libraries, suggesting a common build process or operator.
  • The first stage fetched pepesoft.exe from external hosting and reportedly used DNS-over-HTTPS to resolve GitHub download hosts, reducing the effectiveness of hosts-file blocks and some local DNS controls.
  • Ten of the 11 downloaders requested elevation to resynchronize the system clock before payload retrieval, according to the source.
  • The second-stage payloads used shared AWS-style key material, Google Sheets authentication, hardware identifiers, and a remote HWID/UUID ban-list.
  • In three direct-bytecode payloads, Socket recovered larger game-automation applications with Telegram bot commands capable of sending screenshots.
  • Dormant BitTorrent fallback code was present, but the provided source does not establish that peer-to-peer delivery was active.

Affected ecosystems

NuGet, dotnet tool / .NET CLI tool installations, Windows hosts where the tools were installed or executed, Developer, gamer, and automation environments that install NuGet tools from untrusted publishers

Security analysis

This is a software supply-chain incident because the attacker abused NuGet’s tool distribution model to place executable downloader packages in a public package ecosystem. The social engineering was aimed at users seeking game cheats or automation rather than conventional application libraries, but the risk pattern is the same: a package registry delivered code that executed outside the normal application review path and installed a second-stage payload. The most important AppSec lesson is that NuGet exposure is not limited to project library references. DotnetTool packages are installed and invoked as command-line programs, often globally, and may not appear in the same dependency review workflows used for csproj PackageReference entries. Organizations that allow developers or contractors to install arbitrary .NET tools should include dotnet tool inventories, NuGet cache inspection, and endpoint execution telemetry in their supply-chain monitoring. The available source strongly links the 11 packages through shared downloader behavior, shared key material, a common mutex, and common hosting patterns. However, the snippet does not include the complete package-name list, version set, hashes, or removal status. Scoping should therefore combine named IOCs from the full Socket report with behavioral detection for game-themed NuGet tools that spawn downloaded Windows executables or contact Google Sheets, Telegram, GitHub Releases, Hugging Face, or DNS-over-HTTPS endpoints.

Defender actions

  • Inventory global and local .NET tools using dotnet tool list -g and repository tool manifests; look for unfamiliar game-cheat, bot, panel, trigger-bot, calculator, or RP-themed tools.
  • Review NuGet dependency and tool installation logs for the package names and hashes published in Socket’s IOC list. The supplied snippet names amazing-x-x@7.7.8 as one flagged example but does not include the full set of 11 packages.
  • Remove suspected tools, delete cached package artifacts, and reimage or deeply inspect Windows hosts where the downloaded executable ran.
  • Hunt for execution of pepesoft.exe, PyInstaller-packed binaries launched by dotnet tools, and .NET assemblies under tools/net8.0/any/ with game-themed names such as albion.dll, gta5rp.dll, lineage2.dll, or setup.dll.
  • Check network and endpoint telemetry for downloads from GitHub Releases and Hugging Face paths associated with pepegit666, plus unusual Google Sheets API usage, Telegram bot traffic, and DNS-over-HTTPS activity from these processes.
  • Do not rely only on DNS sinkholes or hosts-file blocking, because the downloader behavior reportedly used DNS-over-HTTPS for some resolution steps.
  • Restrict NuGet tool installation in managed environments, require trusted sources and publisher review, and treat .NET tools as executable software rather than passive dependencies.
