Malicious Go Module Linked to GitHub Lure Network Used for Windows Malware Staging

A fake DNS/subdomain scanning module exposed a broader GitHub-based operation using commit activity, dead-drop infrastructure, and archive payloads to deliver RATs, stealers, and miners.

Socket

What happened

Socket reported a malicious Go module, github.com/kaleidora/dnsub-scanning-tool, that posed as a DNS or subdomain scanning utility while embedding a Windows malware staging chain. The package reportedly executed hidden PowerShell, resolved next-stage infrastructure through public dead drops, retrieved protected archives, and led to payloads including RATs, infostealers, downloaders, spyware/dropper components, and cryptominers. Pivoting from the module, researchers identified a high-confidence cluster of 222 GitHub repositories across 190 accounts that appeared designed to make deceptive projects look active and maintained through synthetic commit activity. Socket says the Go security team blocked the module from the Go module proxy; the full status of GitHub-hosted infrastructure is not clear from the provided source.

Key findings

  • The initial supply-chain entry point was a Go module impersonating a developer/reconnaissance utility rather than a direct exploit of Go tooling itself.
  • The module showed abnormal release behavior: Socket observed more than 1,200 versions, with more than 700 described as malicious, which is highly suspicious for a small recently created tool.
  • The campaign used GitHub repositories as credibility and delivery infrastructure, including apparent commit-farming workflows to simulate project activity.
  • Socket’s confirmed repository cluster includes 222 repositories across 190 accounts, but the source notes this is a conservative core and may not represent the full scope of related activity.
  • Observed malware families and payload classes included AsyncRAT, Quasar, Remcos, Vidar, trojan downloaders, spyware/dropper payloads, and Monero mining components.

Affected ecosystems

Go modules, GitHub repositories and accounts, Windows developer workstations and CI environments that execute untrusted tooling, Security/reconnaissance tooling users searching for DNS or subdomain scanners

Security analysis

This incident is a practical example of package ecosystem abuse rather than a novel vulnerability in Go. The attacker’s advantage came from developer trust: a plausible utility name, a familiar security-tooling theme, active-looking GitHub repositories, and many package versions that could make the module appear maintained. The staging chain then crossed from dependency installation into endpoint compromise by using PowerShell and archive-based delivery to run Windows malware. For AppSec teams, the key lesson is that repository popularity and recent commit activity can be manufactured. Dependency review should combine package provenance, maintainer history, version behavior, install-time or runtime execution patterns, and endpoint telemetry. The public source does not provide complete victim counts, all indicators, or final takedown status for every repository, so defenders should treat the named module and related GitHub activity as known-bad while continuing broader hunts for similar impersonation patterns.

Defender actions

  • Search dependency manifests, module caches, build logs, and developer workstations for github.com/kaleidora/dnsub-scanning-tool and any references to the kaleidora namespace.
  • Treat execution of the module as potential host compromise, especially on Windows systems; review PowerShell logs, process creation telemetry, archive downloads, and outbound connections around the time the package was installed or run.
  • Audit Go projects for unusually high-version, recently created, or namespace-mismatched modules that imitate known tools.
  • Do not rely only on repository activity as a trust signal. Review maintainer identity, release history, code behavior, and whether GitHub Actions activity appears synthetic.
  • Restrict developer and CI execution of newly introduced command-line tools until they have been reviewed, especially tools that invoke PowerShell, download archives, or execute opaque binaries.
  • If exposure is confirmed, rotate credentials accessible to the affected host or CI job, including GitHub tokens, package registry tokens, cloud credentials, and SSH keys.
