LLM Package Hallucinations Leave PyPI and npm Names Open to Slopsquatting

A new study found 53 nonexistent package names repeatedly suggested by five frontier coding models and still available for registration, creating a practical dependency-confusion risk even without evidence of active exploitation.

Socket

What happened

Independent research reviewed by Socket and PyPI Security found that five frontier LLMs generated overlapping nonexistent package names in Python and JavaScript coding responses. After false-positive review, 53 shared names remained available for registration as of April 2026: 41 on PyPI and 12 on npm. The finding does not describe an active compromise, but it identifies plausible slopsquatting targets: package names an attacker could register so that AI-assisted developers install attacker-controlled dependencies.

Key findings

  • The study analyzed nearly 200,000 code-generation responses across five models and found package hallucination rates between 4.62% and 6.10%.
  • Researchers initially identified 127 package names generated by all five models; after review, 53 were still unregistered across PyPI and npm.
  • Python-related hallucinations were more common than JavaScript in this test set.
  • The reported targets are potential abuse opportunities, not confirmed malicious packages or known compromises.
  • The study is posted as a preprint and has not been peer reviewed, so results should be treated as useful but not definitive.

Affected ecosystems

PyPI, npm, AI-assisted software development workflows using LLM-generated dependency recommendations

Security analysis

This is a supply-chain risk rather than a reported breach. Slopsquatting works because LLMs can confidently invent dependency names that look plausible. If multiple models repeat the same nonexistent names, attackers gain a higher-value registration target: one malicious package could be suggested across several AI coding products and workflows. The practical exposure is greatest in teams that allow AI-generated code to add dependencies without registry reputation checks or reviewer scrutiny. The source does not provide the list of all 53 names in the snippet, and there is no evidence that the names were maliciously registered or installed. Defenders should treat this as a control gap around dependency intake, not as an incident requiring emergency package removal.

Defender actions

  • Do not install packages solely because an AI coding assistant recommended them; verify package existence, ownership, documentation, release history, and repository links.
  • Add dependency review controls that flag newly registered packages, low-reputation packages, typosquatting patterns, and packages absent from approved allowlists.
  • Use lockfiles and internal package mirrors or registries to reduce unreviewed dependency introduction.
  • Require human review for new direct dependencies introduced by AI-generated code.
  • Monitor SBOMs, package manifests, and pull requests for unfamiliar PyPI and npm dependencies, especially names with no established project history.
  • Where possible, configure AI coding tools to prefer existing project dependencies or organization-approved package catalogs.

Source notes

  • Socket summarized an independent arXiv preprint by Aleksandr Churilov on LLM package hallucinations across five frontier models.
  • Socket states that PyPI Security and Socket reviewed the candidate names and removed several false positives.
  • The source explicitly says the research identifies potential slopsquatting targets and does not report active exploitation.
