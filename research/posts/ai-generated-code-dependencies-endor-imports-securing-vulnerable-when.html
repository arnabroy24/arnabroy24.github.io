AI coding agents expand dependency risk through vulnerable and invented packages

Endor Labs reports that AI-generated code can add more—and older—open source dependencies, creating exposure to known CVEs and package-name abuse such as slopsquatting.

Endor Labs

What happened

This is not a report of a single compromised package or active breach. The source describes a software supply-chain risk pattern: AI coding assistants may introduce open source dependencies that developers did not explicitly choose or review. Those packages can be outdated, vulnerable, transitive, hallucinated, typosquatted, or otherwise attacker-controlled if a plausible package name is registered and installed.

Key findings

  • Endor Labs says AI-generated code can pull in substantially more dependencies than human-written code, increasing direct and transitive attack surface.
  • The source reports that 49% of dependency versions imported by AI coding agents in its research had known vulnerabilities, though the snippet does not provide the full dataset, ecosystem breakdown, or methodology.
  • A key risk is that developers may review generated application logic but accept the suggested dependency and lockfile changes with less scrutiny.
  • Hallucinated package names create an opportunity for slopsquatting: attackers register packages matching names that AI tools are likely to invent.
  • The most serious exposure may be hidden in transitive dependencies, where vulnerable code is less visible to the developer who accepted the AI suggestion.

Affected ecosystems

Open source dependency ecosystems used by AI-assisted development; the source does not name specific registries or packages., Applications that allow AI coding tools to modify manifests, import statements, install commands, or lockfiles., Build pipelines that rely only on late CI scanning rather than validating dependencies when they are introduced.

Security analysis

The practical AppSec issue is not that AI-generated code is automatically unsafe; it is that AI tools can quietly become dependency selectors. When an assistant adds an import or installation command, it may also expand the transitive dependency tree. If the model learned from older examples, it may choose stale versions with known CVEs. If it invents a plausible package name, an attacker can exploit that trust gap by publishing malware under the hallucinated name. This makes AI-assisted development a supply-chain control problem as much as a code-review problem. Organizations should ensure dependency policy is enforced at the moment a package is introduced, not only after it has already entered the build. The source does not identify a specific malicious package campaign, so defenders should treat this as a risk model and control gap rather than an incident with a defined IOC set.

Defender actions

  • Treat AI-suggested imports, package installs, and lockfile changes as untrusted supply-chain input requiring review.
  • Require automated checks in the IDE, pre-commit hooks, and CI for package existence, version age, known vulnerabilities, malware indicators, license policy, and maintainer/provenance signals.
  • Review both direct and transitive dependencies introduced by AI-generated code, not only the top-level package.
  • Alert on new packages with low maturity, suspicious naming similarity, unusual maintainer changes, or little usage history before allowing installation.
  • Use lockfile and SBOM diffing in pull requests so reviewers can see exactly which dependencies were added by an AI-assisted change.
  • Prioritize remediation with reachability or runtime evidence where available, so teams focus first on vulnerable dependency code that the application can actually execute.

Source notes

  • Source: Endor Labs, “When AI Imports Vulnerable Dependencies: Securing AI-Generated Code,” published July 13, 2026.
  • The source provides aggregate claims about AI-introduced dependency risk but the snippet does not include package names, affected registries, IOCs, or full research methodology.
  • No duplicate incident coverage was present in the provided sources.
