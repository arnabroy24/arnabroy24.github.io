Malicious @bitwarden/cli release targeted developer secrets through npm install hooks

A compromised Bitwarden CLI npm package briefly exposed users of @bitwarden/cli 2026.4.0 to a payload that reportedly harvested CI credentials and attempted to propagate through npm projects.

Endor Labs

What happened

Bitwarden’s npm-distributed CLI package, @bitwarden/cli, was reportedly compromised in version 2026.4.0 on April 22, 2026. According to the available source, the malicious release was live on npm for about 90 minutes, from approximately 5:57 PM to 7:30 PM ET, before a clean follow-up version was published. The package is high impact because the Bitwarden CLI is commonly used in developer automation and CI/CD workflows to retrieve secrets. The source attributes the compromise to a chain involving Checkmarx GitHub Actions used in Bitwarden’s repository, but the full intrusion path remains incomplete from the provided material.

Key findings

  • Affected package: npm package @bitwarden/cli, specifically version 2026.4.0.
  • The last known clean version cited by the source is @bitwarden/cli 2026.3.0; a clean replacement, 2026.4.1, was reportedly released on April 23, 2026.
  • The malicious package added new files, including bwsetup.js and bw1.js, and modified package.json to execute bwsetup.js during preinstall.
  • The package’s CLI entry point was reportedly redirected so invoking bw would run the attacker-controlled bootstrap path rather than the normal built CLI bundle.
  • The payload is described as collecting CI secrets such as SSH keys and API tokens and exfiltrating them to public GitHub repositories created under victim namespaces.
  • The source says the campaign also attempted worm-like propagation through victims’ npm projects, similar to prior Shai-Hulud activity.
  • A Bun runtime check and download path were used as part of the stager, with an obfuscated secondary payload executed afterward.

Affected ecosystems

npm packages and JavaScript/Node.js build environments, CI/CD systems that installed @bitwarden/cli 2026.4.0 during the exposure window, Developer workstations or automation hosts where the Bitwarden CLI was installed or invoked, GitHub accounts and repositories associated with exposed developer or CI credentials, Downstream npm projects that may have been modified if the propagation behavior executed successfully

Security analysis

This incident is a direct software supply-chain compromise: a trusted package used as developer infrastructure allegedly shipped attacker-controlled install-time code. The most important exposure question is not only whether an application imports Bitwarden code, but whether any build, release, or automation environment installed the specific npm version during the short publication window. Because npm lifecycle scripts run during installation, compromise could occur even if the CLI was never intentionally invoked after installation. The attacker’s choice of @bitwarden/cli is significant. Password-manager CLIs often run in privileged automation contexts and can be adjacent to the very credentials needed for release, deployment, and repository access. The reported preinstall hook and CLI entry-point redirection gave the malicious code multiple chances to execute: during dependency installation and during normal bw command usage. The source links this incident to a prior compromise of Checkmarx GitHub Actions used by Bitwarden, but the provided information does not fully establish each step from that compromise to npm publication. Defenders should therefore separate confirmed local exposure indicators — installation of @bitwarden/cli 2026.4.0, suspicious files and scripts, unexpected GitHub repositories, and credential use — from still-developing attribution or root-cause claims.

Defender actions

  • Search package-lock.json, npm-shrinkwrap.json, pnpm-lock.yaml, yarn.lock, SBOMs, build logs, container layers, and artifact metadata for @bitwarden/cli@2026.4.0.
  • Treat any system that installed or executed @bitwarden/cli 2026.4.0 as potentially exposed, especially CI runners with access to deployment keys, npm tokens, GitHub tokens, cloud credentials, or Bitwarden-derived secrets.
  • Upgrade to a known clean release and avoid reinstalling from cached package artifacts that may still contain the malicious version.
  • Rotate secrets available to affected CI jobs or developer environments, including SSH keys, API tokens, npm publishing tokens, GitHub tokens, cloud credentials, and service account credentials.
  • Review GitHub accounts and organizations for unexpected public repositories, suspicious commits, new workflow files, altered package manifests, or unauthorized npm package changes.
  • Inspect affected projects for unexpected package.json lifecycle scripts, altered bin entries, newly added JavaScript payload files, or unauthorized package publication activity.
  • Harden CI by minimizing long-lived credentials, scoping tokens per workflow, disabling unnecessary package lifecycle scripts where feasible, and requiring provenance or trusted publishing controls for release pipelines.

Source notes

  • Endor Labs reports that @bitwarden/cli 2026.4.0 was malicious and available on npm for roughly 1.5 hours on April 22, 2026.
  • The same source identifies added files bwsetup.js and bw1.js plus package.json changes involving a preinstall script and modified CLI bin mapping.
  • The source states the malicious behavior included CI secret theft, GitHub-based exfiltration, and npm-project propagation, but the full compromise chain is described as still developing.
